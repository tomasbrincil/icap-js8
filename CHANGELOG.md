# Changelog

## 0.2.1 - clearer screen texts, operator's manual

State of 25 November 2026. Build id `331e7`. **This build has run only in the simulator so far**; the build `2858` before it (the same screen texts except CQ, which it still had, and one renamed row) ran on the author's radio on 24 November.

**Changed**

- DECODE rows without SNR and audio offset: `HHMM TEXT`, `HHMM > TEXT` (to you), `HHMM = TEXT` (complete multi-part message), `HHMM ? TEXT` (checksum did not verify). SNR and offset stay in the log.
- A JS8 frame is called a **part** on the screen, because "frame" there is the red or green frame of the mode tile: `2 parts: MODE > hold FT8 (red), 2 min`, `TX refused: part 3/3 - red frame again`, `TX: slot missed, MODE > hold FT8 (red)`.
- After sending: `SENT: <text>` (and `red frame off to tap again` while the red frame is on); after a heartbeat of `txhb=`: `HB SENT, next in N min`; with the beacon on: `red off = MODE > hold FT8 again`.
- `HHMM ? TEXT` wins over `>`: a message to you whose checksum did not verify is marked `?`.
- `KBD: return arrow not seen - use ENT` (was `KBD: cannot see EXIT - finish with ENT`); the status in the app window says `GREEN unused` instead of `CQ ARMED`.

**Removed**

- **CQ** (owner decision 24 November 2026). The green frame is not used: an arming of it sends nothing and asks the radio for nothing; the row `green not used - hold FT8 again` says so. (In the one try before, the CQ had expired unsent.)

**New**

- Operator's manual in the style of a printed technical manual, English and Czech PDF in `docs/manual/`; the screen pictures are drawn with BI1BIF's emulator of the radio and the rows in them come from runs of the app in the simulator.

**Known**

- While a one-part reply on the tap credit is on the air, the radio itself shows the green frame.

## 0.2.0 - transmit with the radio's own keyboard

State of 24 November 2026.

**New**

- **Transmit.** `FT8.APP` (receive + transmit; it must have this file name on the card, the loader gives slots and arming only to it). Tap a decoded row, the radio's own keyboard opens prefilled with the station's call, ENT sends. A one-frame text goes out at the next slot on the loader's tap credit without arming; a longer one after the red-frame (beacon) arming, its frames in consecutive slots. Prepared replies to queries (`SNR?`, `GRID?` ...). HB beacon with `txhb=`. One CQ per green-frame arming (not yet tried on the radio; removed in 0.2.1). Cancel and stop: red frame off, an empty ENT / `X` / `CANCEL`, a tap before a granted slot, EXIT / STOP / PTT during a frame.
- **The radio's keyboard** is opened by direct calls into the IC-705 firmware (705J 1.40 / SQ6EMM 20261119v14 J only, guarded by a check of the code at the three addresses; entry points found by BI1BIF). See "Safety" in the README.
- **Safety rule** enforced in `src/js8tx.c`: a frame only for a text seen whole and confirmed with ENT, only on the loader's tap credit or the owner's arming; transmitting off unless `tx=1`; caps per message and per run.
- **Dictionary in the card root** (looked up there first, then in `\IC-705\Apps\`), checked file by file against `JSCSUM.BIN`; the full dictionary (515 files) is generated by `tools/mkjsc.py`, the encode half is needed for free text.
- `JS8.CFG`: key names in any case, blanks around `=`, comment lines, a byte-order mark is skipped; transmit keys `tx`, `txhb`, `txsess`, `txtest`, `kbdirq`, `popup` and others.
- Log files as write-once segment files, a state file pair.
- Tests: the transmit engine (`make t7`), the RX+TX app in the simulator with loopback through the decoder (`make txe2e`), the keyboard control (`make fixe2e`); all part of `make test`. `make arm-all` builds both apps; `make dist` lays out the card.

**Measured on the radio** (one IC-705 J, 7.078 MHz, 5 W, 23-24 November 2026, the builds leading up to this release): the first HB from the radio heard by M7ECR at 923 km (JS8Call, 23 November); an HB typed on the radio's keyboard sent on the tap credit without arming and answered by six stations; a two-frame reply in consecutive slots under one arming; a text with a comma after the dictionary was moved to the card root; spotted by F4VTQ/U at 630 km (UberSDR, 24 November 11:03 UTC); multi-frame messages decoded.

**Changed**

- `JS8.APP` (receive only) is built from the same sources and has the root dictionary lookup and the new logs; it contains no transmit code.
- The raw touch byte suggested by the emulator is not read any more (on the radio it does not mean "finger off the screen"); the keyboard opens 800 ms after the tap.

**Not in it**

- No terminal link, no network code in the released apps. Station views, ADIF logging, presets and keyer memories exist in the code experimentally and are not documented (`ROADMAP.md`).
- No Icom firmware (only three addresses and twelve instruction words that are compared, `NOTICE.md`). No recordings. No program binaries, no dictionary files.

## 0.1.0 - first public release: receiver only

State of 23 November 2026.

**What is in it**

- `JS8.APP`, a receive-only app for the Icom IC-705 with the ICAP loader (custom firmware by Dawid SQ6EMM, release 20261119v14): JS8 submode Normal, text on the DECODE screen in rows of at most 40 characters, multi-frame messages joined, JSC dictionary on the SD card, frame and message logs, `JS8PERF.TXT` with decode times.
- The decoder with a streaming front end (the first waterfall is built while the period is captured), faster FFT and LDPC kernels, residual passes made only on evidence, and a time budget per period.
- `JS8.CFG` tuning keys and three presets (`sd/presets/DEFAULT.CFG`, `FAST.CFG`, `DEEP.CFG`).
- The host simulator of the loader (`tests/js8sim.c`), a test signal generator and the test suites.
- Tools: dictionary generator, fetch script for the SDK and the JS8Call reference files, SD-card file set.

**Measured on the radio** (one IC-705 J, 7.078 MHz, 23 November 2026, default settings, one run of 35 periods = under 9 minutes): decode time 2.7 s on average, 1.1 s for an empty period, 8.0 s once, no period cut, no audio gaps, no errors. Details and the history of earlier builds: `docs/PERFORMANCE.md`.

**Not in it**

- No transmit code, no terminal link, no network code. Transmit is under review and not published, see `ROADMAP.md`.
- No Icom firmware or anything derived from it. No recordings. No program binaries, no dictionary files (you generate them).

**Known issues**

- Only submode Normal. No comparison with JS8Call yet.
- The Apps list of the test radio showed at most 8 apps, and the app rescan was noticeably slow with the dictionary's 257 files in the Apps folder.
- The firmware's PSKReporter spotting, DECODE > SET, beacon arming and row taps are not used by this app.
- See "Limitations and known issues" in the README.
